## Bugs found → fixed in this branch

1. **P2 — Empty answers graded CORRECT on mc/gap** (`services/grading.py`):
   `"abcd".find("")` returns 0, so a blank submission matched choice "a" —
   correct whenever the first choice was the answer (verified live: XP/accuracy
   inflated). Fixed: empty/normalized-empty answer finds no index. Regression
   test included.
2. **P2 — Placement unlocked the wrong missions** (`api/routes_path.py`):
   `_mission_rows` ordered by `(parent_id, position)` where `parent_id` is a
   random hex unit id — effectively a random order. A B2 placement marked a
   scattered set of 8 missions done and left `current` pointing at the first
   A1 mission; a fresh-flow A2 placement marked the A2 missions themselves done
   and told the learner to start from A1 greetings. Fixed: missions are now
   ordered in true curriculum order (level → unit → position, the same order
   the tree displays) and `PLACEMENT_MAP` updated to land `current` on the
   first mission of the placed level (3/6/9). Regression tests for A2 and B2.
3. **P3 — Mission completion without attempts trusted the client body**
   (`api/routes_lessons.py`): the fallback the code comment claimed could not
   inflate XP let `{correct: 999, total: 1000}` through as a 100% / 40 XP
   completion. Fixed: completion with zero recorded attempts is refused (400);
   the UI always grades through `/api/attempts`, so only forged or buggy calls
   hit this. Regression test included.
4. **P3 — Stats unreachable below 900 px** (`index.html`): the mobile bottom
   bar markup had only 4 of the 5 nav buttons — `data-nav="stats"` was missing,
   so Stats disappeared entirely on narrow windows (the desktop app allows
   resizing down to 375 px). Fixed: button added; regression test asserts the
   bottom bar mirrors the sidebar. Verified live at 390 px.
5. **P4 — Degraded-mode hints were stale**: they said "Start LM Studio or
   Ollama and POST /api/runtimes/scan" — no such endpoint (it is the Models
   screen rescan) and oMLX, the primary runtime, went unmentioned. Copy fixed
   in `pipelines/__init__.py` and `api/routes_chat.py`.

## Reported, not fixed (deliberate, awaiting product decision)

- **Chat history is not restored after a reload** (P3 UX gap): the UI starts a
  new tutor session on every Tutor visit; there is no `GET` messages endpoint.
  Data is not lost — every diagnosis persists server-side (verified through a
  mid-judge reload) and errors still flow to Review — but the visible
  conversation thread is gone after a reload. Restoring the last unfinished
  session is a behavior decision, not a defect fix.
- **Silent empty transcript on undecodable audio** (P4 hardening): posting
  garbage bytes to `/api/voice/transcribe` returns `200 {"text": ""}` instead
  of a decode error (found while testing with a multipart body by mistake —
  the UI itself sends the correct raw body). A decode failure should surface
  as 4xx/5xx.

## False alarms investigated and dismissed (root-caused, not "fixed")

- Mission circles at different heights → **design**: `.mnode:nth-child(even)
  { transform: translateY(14px) }` is the intended stagger (and it is disabled
  below 900 px on purpose). Found via DOM measurement after the vision model
  flagged it; frozen design area, untouched.
- Missing diagnosis card → **wrong test selector**: the card's class is
  `dx-card`, not `[class*=diagnos]`. EventSource logs proved the event arrived;
  the card renders correctly.
- Shell↔sidecar "VERBA_READY never printed" → **wrong layer**: the dev CLI
  entry hardcodes port 8000, but the packaged `sidecar_entry.py` does print the
  contract line and picks a free port (verified in the DMG run).

  listening/unknown-kind, SRS "hard" grade, lowercase-"i" pre-pass rule,

  calques ("I am agree", "I have 25 years", "I am here since", "informations",
  "explain me", "I want that you") all caught, score floor 40 held, diagnosis
  persisted.
- Known machine gotchas re-confirmed: macOS has no `timeout` command (use
  `curl -m`); `lsof` truncates COMMAND to 9 chars; PyInstaller onefile shows
  two PIDs; the backend sends no `Cache-Control` on `/` so browsers may serve
  stale HTML across code changes in dev (hard-refresh or cache-bust) — a
  no-cache header for the HTML shell is a possible small improvement.
