## Findings

### HIGH

#### attacker-1 — API locale su 127.0.0.1:8000 senza autenticazione né validazione Host/Origin
- **File**: `src/verba/main.py:161` (serve() bind; middleware CORS a main.py:63-68)
- **Rilevato da**: attacker security · **Verificato da**: verifier security indipendente
- **Severità**: HIGH (impatto medio-alto: azioni arbitrarie sull'app locale; probabilità: qualsiasi pagina web visitata durante l'uso; sfruttabilità: banale — nessuna credenziale necessaria)
- **Descrizione**: l'unico controllo d'origine è il CORS, che non impedisce l'**invio** di richieste semplici cross-origin (solo la lettura delle risposte). Una pagina web arbitraria può quindi fare drive-by `POST /api/shutdown`, generazioni LLM, grading, e — via DNS rebinding (Host header dell'attaccante) — anche leggere le risposte. Verificato con grep: zero occorrenze di TrustedHost/token/check Origin; test empirico con TestClient citato dal verifier.
- **Evidenza**: `app.add_middleware(CORSMiddleware, allow_origins=["http://127.0.0.1", "http://localhost"], allow_methods=["*"], allow_headers=["*"])` — nessun altro guard in tutto il backend.
- **Patch proposta**: [security.patch](patches/AUDIT-20261001-163634/security.patch) (middleware local-only: Host allowlist + rifiuto di Origin cross-origin; opzione più forte v0.2: token shared-secret shell→sidecar)
- **Rischio residuo se non corretto**: qualsiasi sito visitato mentre Verba è aperto può fermare l'app, sprecare token GPU del modello locale o manipolare lo stato di apprendimento.
